C# Weather API

A console application that takes location input, requests current conditions from Open-Meteo, and turns a JSON response into a readable weather report.

RESTAPI INTEGRATION
JSONSTRUCTURED RESPONSE
C#APPLICATION LOGIC

THE APPLICATION

The user enters a city name, latitude, and longitude. The program requests weather data and displays conditions, temperature, apparent temperature, humidity, and wind speed, including Celsius/Fahrenheit and km/h/mph conversions.

UNDER THE HOOD / REPRESENTATIVE CODE

Program.cs · C# / .NETView source ↗
string url = $"https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}" +
             "&current=temperature_2m,apparent_temperature," +
             "relative_humidity_2m,wind_speed_10m,weather_code";

using HttpClient client = new HttpClient();
string json = await client.GetStringAsync(url);
WeatherResponse weather = JsonSerializer.Deserialize<WeatherResponse>(json);

double tempC = weather.current.temperature_2m;
double tempF = (tempC * 1.8) + 32;
double windMph = weather.current.wind_speed_10m * 0.621371;
Why it matters

This is the core integration path: construct an external-data request, wait for the response asynchronously, deserialize structured JSON, transform the returned values, and present them in a form a user can understand.

TECHNICAL BUILDING BLOCKS

  • Asynchronous requests: HttpClient with async / await.
  • Typed data: JSON deserialization with System.Text.Json and custom response classes.
  • Application logic: input handling, unit conversion, and weather-code interpretation.

WHY IT BELONGS HERE

It demonstrates a complete path from external data to useful output: collect input, construct a request, work with the response, and explain the result to a user.

Scope & limitations

This is a .NET console application originally developed for a programming course. The portfolio visual is illustrative; the actual application runs as a console program and is documented in the repository.
